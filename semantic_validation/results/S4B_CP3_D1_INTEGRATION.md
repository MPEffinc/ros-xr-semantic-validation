## Implementation and decision-path boundary

The trial-owned code is under [`runs/s4b_cp3_d1_path_20260923T035434Z/inputs/`](runs/s4b_cp3_d1_path_20260923T035434Z/inputs/). No vendor checkout was edited. `d1_contract.py` binds original payload and source state in one envelope with a SHA-256 payload hash; the restore stage checks only transport integrity and performs no independent validity/freshness/recovery decision. B1 decides before the original receiver. B3 checks in an original Mapper callback subclass, not in a generic ROS relay. B2 runs the generated **official** ROSMonitoring 3.0.0 monitor and real TLOracle/Reelay property. I_NATIVE sees wire fields but not a verifiable original generation/age; I_FULL carries sample ID, generation, native state and source time. I_NATIVE cannot stand in for I_FULL.

Reelay 25.0.0 and websocket-server 0.6.4 were pinned as trial-local wheels. The B2 transport is `receiver → /s4b/d1/{envelope|native_input}_mon → official filter + oracle → base topic → lossless type restore → original mapper/bridge → Servo → controller → Gazebo`. The first setup showed the generated monitor's actual `_mon` subscription orientation differed from the initial remap assumption. That failure is preserved. The second full setup exposed a property bug: intentional ungripped neutral inputs were blocked. The property was corrected without changing frozen policy. This is stronger than fixed sleep, but **not yet the complete frozen all-participant clock/ACK contract**: individual monitor/oracle/sender clock identities and end-to-end output-parent instrumentation are incomplete.
