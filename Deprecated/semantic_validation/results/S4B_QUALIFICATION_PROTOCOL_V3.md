## Normative scope and D1 gate

This version only governs **new** process/resource, latency and ordinary-stop setup qualification for Docker D1. The original policy, native validity/freshness/future-time/generation semantics, R_EXPLICIT/R_AUTO rules, D1 20 Hz 120-index pose/phase fixture, sample order, initial arm vector, Servo/controller settings, B0/B1/B2/B3 information regimes, monitor implementation/property, 5 ms source schedule, 0.02 rad allowed-path tolerance, >0.01 rad motion, <=50 ms stop request, <=300 ms no continuing new motion, <=1 s joint settling, five formal repetitions and seed 20260922 are unchanged. There is no new defense algorithm. The official B2 remains ROSMonitoring 3.0.0 at `d03aa5b44e29b76c0e108a098817bdf5aa98e322`; B2-native and B2-composed stay distinct.

XRROS-S4-1.0.0 §6 calls confirmed Docker zero twist plus halt an S4-B **setup prerequisite** and gives B1/B3 the same stop service/adapter contract as B2-composed. D1 normal input never triggers that stop, so a separate **qualification-only stop stimulus** is needed before formal D1. It is not a D1 formal trial or an invalid-state defense result. Apply it to B1, B2-composed and B3 using the same ordinary adapter and original Servo/controller; B2-native retains unmodified native failure behavior. The qualification stimulus is an explicit adapter stop request at common barrier +2.25 s, within the registered active D1 interval. The source fixture stays identical; the request is labelled `QUALIFICATION_STOP`, not a source/oracle policy verdict. Require measured nonzero controller output and joint motion **before** trigger, log stop trigger/request/service reply/last new nonzero controller output and full joint settling (velocity <.001 rad/s, drift <.0001 rad over .5 s by trigger+1 s). If the arm was already stopped or a pre-existing Servo timeout stopped it, result is INVALID/UNKNOWN, not stop PASS. No recovery/re-arm test is part of D1; D5/D6 require separate R_EXPLICIT/R_AUTO qualification. C-MON oracle disconnect/health-fault comparisons also require their own stimulus. The adapter may not independently inspect XR validity, source age, generation or recovery.

For D1 normal acceptance, exact sample ID/native-state/payload association must reach the original callback and Servo input callback; repeated cached commands retain their selected source ID and distinct child command ID. A specific source sample to individual Servo output, controller output or Gazebo joint sample is **not** required for D1 interval-level output/movement scoring under §8, and must remain UNKNOWN absent an actual parent trace. For cases using §8 forbidden-acceptance event-level scoring, the requisite parentage/decision-time join must be separately qualified; D1 cannot license those cases. Do not use timestamp proximity as an exact join.

## Single bundled implementation change and limits

Copy the frozen Q2 execution sources/configuration into a **new** result root; keep Q2 inputs and raw immutable. Before the first Q3 runtime, freeze together: a 100 ms procfs process-tree sampler; monotonic source/gate/oracle/consumer observation and ID-join analyzer; a qualification-only stop-request input to the existing generic adapter; recorder/start ACK for the sampler; trial launcher/analysis, unchanged fixture and official generated monitor/property hashes. Changes are observation/setup only except for an explicit ordinary stop request in the separate diagnostic. B0 remains unmodified. If monitor forwarding is observed only at a downstream callback, label it `forward_received`, not exact internal `t_forward`. Any generated-monitor instrumentation requires its own non-defense diff and B0/shim equivalence; it is not assumed necessary here. ROS header/sim time is never subtracted from host monotonic.

Resource sampler must record every 100 ms: monotonic sample time, boot ID/time namespace, root and descendant PID, process start tick (PID reuse key), user+system CPU ticks converted using recorded `SC_CLK_TCK`, RSS pages converted using recorded page size, and missing/ended process states. Record process CPU time distinct from wall time; never fill a missing sample with zero. Capture the sender, gate/observer, official monitor, oracle, original receiver/mapper/bridge, Servo, controller/Gazebo and recorder where present. If a required process is unidentifiable or sampling gaps prevent the registered CPU/RSS metric, mark it UNKNOWN/INVALID rather than interpolate. Formal CPU% and incremental overhead follow original §8 exactly.

Latency analyzer joins **actual IDs and canonical payloads** along source generation, source gate/receive, selected cached input, original mapper/bridge publication, Servo callback and observable downstream messages. Use same verified CLOCK_MONOTONIC boot/time namespace and uncertainty <=1 ms. Record source→callback min/median/p95/max and per-trial max; gate/oracle→consumer only where same-ID join exists. The official oracle property log gives its own monotonic decision observation; generated monitor status wall time is **not** converted to exact monotonic forwarding time without calibrated instrumentation. Required unobservable stage-local times are UNKNOWN. The original §8 p95 added gate/transport target <=20 ms remains unchanged; no fabricated B0 stage timestamp.

## Preflight, freeze and finite attempts

Before any Q3 Gazebo runtime: independently test sampler on a known parent+child that starts and exits, deliberate PID/start-tick mismatch, missing process, and >=50 measured intervals with required period/record schema; test ID joins with CP4 raw, duplicate payloads and missing parent; verify clock-domain labels; test that the adapter consumes only ordinary stop/verdict/health events and has no XR predicate; verify 120/120 sender, child nonzero propagation, official monitor/property/remap and full graph/start ACK code. Preserve every failed preflight and correction. Do not run runtime with a failed mandatory preflight. A process-resource test alone is not Gazebo qualification.

Commit-push and verify **code/config/fixture/analysis/protocol SHA freeze before the first new Q3 runtime**, including Docker image ID, official monitor revision/generated source, source fixture SHA, start barrier, sampler, stop stimulus, analyzer, trial schedule for qualification and finite retry ledger. One initial integrated setup plus **at most two setup-only retries per named Q3 cell** `(baseline, regime, normal-or-stop diagnostic)`; failed attempts remain. Fix preflight errors only before freeze. After freeze, environment-only corrections within fixed code/config consume a retry; code/policy/fixture/topic/analysis-rule changes invalidate affected trials and require a separately preregistered future version, not silent Q3 reuse. A functional policy violation is scored, never retried to success. Exhaustion BLOCKS the affected cell; do not automatically create Q4.

Q3 normal-path qualification reruns B0, B0-shim, B1/B2-native/B2-composed/B3 in I_NATIVE/I_FULL with the exact Q2 fixture and fresh initial Gazebo state. Recheck B0/shim equivalence (max source-index difference <=5 ms and final joint difference <=.02 rad) because instrumentation changed; Q2 normal-path PASS cannot be inherited wholesale. Require 120/120 source IDs, equal information per regime, all-participant clock/recorder/controller/Servo/monitor-oracle ACK, original callback and exact source-parent→Servo-callback joins, post-barrier controller output and >.01 rad Gazebo motion. Check 100 ms resource series and computable latency/overhead separately; an output positive control does not prove measurement completeness. The stop diagnostic verifies actual stop contract for B1/B2-composed/B3; B2-native diagnostic stays separate. D1 does not require D5/D6 jump-free re-arm or C-MON disconnect behavior.

Only if every **D1-applicable** setup/stop/clock/lineage/measurement gate passes, create a **separate** formal configuration/schedule SHA freeze commit, with five fresh-state repetitions per baseline/information regime, B0-shim and B2-native diagnostics separately retained, order randomized using seed 20260922, all implementation/config/fixture/oracle/analysis hashes and no outcome-based adaptation.
