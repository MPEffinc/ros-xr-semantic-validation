## Prospective resource method and no-Gazebo tests

CP6-A candidate `analysis/sender_lifecycle_wrapper.py` launches the unchanged sender argv as a child, waits with `os.wait4`, records child PID/start tick, return code, final user/system CPU and peak (`ru_maxrss`) RSS, and leaves a **non-sending observational parent** alive until an explicit capture-end marker. The child itself is not held alive or made to transmit longer. Its wait4 return time only bounds the actual exit from above; `ru_maxrss` is a peak, never a claimed RSS at exit. The parent exists so procfs 100 ms sampling can see its own ticks and waited-child ticks after sender termination. For a single waited sender child, live child and waited-child ticks are mutually exclusive; descendant inclusion must be checked per actual tree and not summed twice. This introduces observational overhead, requiring new B0/shim equivalence and across-arm freeze before runtime.

`analysis/lifecycle_resource_audit.py` defines a capture-window CPU metric only from **observed first and last in-capture periodic/boundary snapshots**: delta of tree own+waited ticks divided by `SC_CLK_TCK` and by the measured monotonic interval between those snapshots. This is not whole-process CPU; wait4 whole-child CPU is a separate cross-check. A measured additional capture-end boundary snapshot closes the interval when a child exits after the last 100 ms tick. No missing sample is zero-filled, no RSS after child exit is imputed, and a changed PID/start identity, missing periodic index, missing final accounting, abnormal child exit, or no post-wait4 capture snapshot remains UNKNOWN. The actual boundary acquisition interval needs recording in the runtime implementation; a long boundary read cannot be described as an exact instantaneous sample. A child exiting after capture end yields a valid final whole-lifetime wait4 record but **not** a substituted capture-window metric under this candidate analyzer.

`analysis/test_lifecycle_preflight.py` ran host-only scenarios A–I. All nine tests met their declared classification: planned normal exit, exit during 100 ms sampling, exit near capture end, and waited CPU-using descendant returned PASS; exit after capture end, abnormal exit, PID/start identity change, running periodic-index loss, and missing final accounting returned UNKNOWN with explicit reasons. The first implementation had a malformed synthetic child command (recorded in this checkpoint's analysis history); it was fixed before any freeze or runtime. A trial without the extra boundary snapshot also returned `NO_POST_WAIT4_PERIODIC_SAMPLE_INSIDE_CAPTURE` near the end; that observed failure motivated the boundary-snapshot candidate, not a relaxation of the Q3 verdict. Host preflight is not integrated ROS/Gazebo proof.
