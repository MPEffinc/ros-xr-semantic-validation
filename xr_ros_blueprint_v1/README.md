# XR→ROS 연구: 무엇을 확인하고 어떻게 진행하는가

우리가 보는 문제는 **XR에서 만들어진 조작과 사용자의 승인이 ROS의 실제 실행까지 올바른 의미로 이어지는가**다. 입력, 중단·재개, 시각과 좌표, 권한, 로봇 실행, 화면·승인, 개인정보와 가용성을 함께 본다.

기존 실험은 그중 입력 활성 증거와 stop/resume 일부를 검증했다. 마지막 실제 앱에서는 독립 수신 gate가 추가로 막은 명령이 0건이었다. 따라서 그 gate의 확대는 보류했지만, 다른 사례나 공통 시스템의 가능성까지 부정한 것은 아니다.

## 앞으로 진행하는 순서

1. **지도 확인:** 사례 40개의 보호 조건, 공격 권한, 기존 연구, 구현 근거와 남은 한계를 연결한다.
2. **사례 검증:** 기존 방어를 제대로 적용한 비교군을 먼저 만든 뒤 정상 조건과 문제 조건을 함께 시험한다.
3. **남는 것 구분:** 구현 누락, 증거 부족, 신뢰 문제, 지연·집행 문제, 반복되는 통합 비용을 구분한다. 해결돼도 한계를 남긴다.
4. **시스템 평가:** 여러 사례와 서로 다른 실제 경로에 공통 구조가 필요하다면 작은 시스템을 만들어 개별 수정 및 관련 프레임워크와 비교한다.

첫 묶음은 **중단 → 실제 정지 → 재허가 → 기준점 재설정**이다. 다음은 시간·출처·우회, 그다음은 화면에서 고른 대상과 실행 대상의 연결이다. 공간·장치, 통신·privacy는 이어서 감사한다. 40개를 동시에 실행하지 않는다.
